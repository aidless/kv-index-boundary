# 稀疏注意力边界曲线实验设计

目标：实测「索引式稀疏 attention 何时反超 dense」的边界，与字节模型交叉点对齐，
产出一张可放进作品集的边界图 + 一篇博客。

## 假设声明（开工前对齐）

1. 实测对象是 **内存流量物理**，不是生产 kernel。用 PyTorch gather+bmm 模拟
   「索引扫全量 + 取 top-k」的读写模式，生产 kernel（FlashMLA/DeepSelect 的
   radix-select）会在此基础上加选择开销。所以本实验测的是**机制成立的边界**，
   生产收益只会更差不会更好——结论方向可迁移，绝对毫秒数不可直接引用。
2. 多头折叠进 batch 维。字节模型里每 token 每层的读取量与头数无关
   （头数只改切分方式），折叠不改变流量。
3. fp8 字节量用 fp16 元素数模拟：KV 维 288 元素 × 2B = 576B/token/层，
   索引维 64 元素 × 2B = 128B/token/层。逐字节还原 DSA 口径。
4. 正式扫参上云（Kaggle T4 或 AMD MI300X），本机只跑亚分钟级 smoke。

## 可证伪预测（预注册）

- **P1（核心）**：实测 sparse/dense 时间比随 N 收敛到字节模型预测值
  `(d_I·N + d·k)/(d·N)`，128K/k=2048 处 ≈ 0.238。
- **P2（边界）**：sparse 反超 dense 的临界 N* ≈ `k/(1 − d_I/d) = k/0.778`。
  k=512 → N*≈658；k=1024 → N*≈1317；k=2048 → N*≈2633。
- **P3（可迁移性）**：**时间比与 GPU 带宽无关**（两个路径同带宽-bound，
  比值是纯字节量之比）。T4 与 MI300X 测出的边界应一致，绝对毫秒不同。
  这条成立的话，结论可以跨硬件引用。
- **P4（batch 不改变比值）**：时间比不随 batch 变。batch 改变的是
  「KV 带宽是否超过权重带宽」的绝对重要性，不是比值本身。

证伪标准：实测临界 N* 偏离预测 >1.5×，或 implied bandwidth < 峰值 30%
（说明测量被 launch 开销污染，不是带宽-bound，全部读数作废重测）。

## 变量与网格

| 变量 | 取值 | 说明 |
|---|---|---|
| N（KV 长度） | 4096, 8192, 16384, 32768, 65536, 131072 | 上下文轴 |
| k（top-k） | 512, 1024, 2048 | 选择轴 |
| B（batch×头折算） | 1, 8, 32 | 并发轴 |
| 固定 | d_KV=576B, d_I=128B, L=60（层乘数在分析时加） | DSA 口径 |

显存核算（最重配置）：B=32, N=131072 → K+V 各 2.4GB + 索引 0.54GB ≈ 5.4GB，
T4 16GB 放得下；本机 6GB 只跑 smoke（自动砍网格）。

## 步骤 → 验证（每步过了才进下一步）

1. **selftest**：k=N 时 sparse 路径必须逐元素还原 dense 输出
   （atol 1e-3，fp16）。红不了说明 sparse 路径写错了。
2. **smoke**（本机，<1min）：小网格跑通，CSV 落盘，implied GB/s 在
   3060（峰值 ~360GB/s）的 30% 以上。
3. **云端全网格**：T4 上 ~54 配置，预计 5 分钟内。CSV append 可断点续跑。
4. **分析**：临界 N* 实测 vs 预测表 + 边界图（每 batch 一张，比值曲线）。
5. **写作**：博客骨架在分析输出上生成，数字全部来自 CSV，不手打。

## 附加产出（纯算术，不需要 GPU）

权重带宽 vs KV 带宽交叉点表：`B·L·576·N = W`（W 为每步权重读取字节）。
取 W=50GB/100GB，算出 KV 开始主导的 batch 临界值——回答「这 3/4
在什么并发下才变成真收益」。
